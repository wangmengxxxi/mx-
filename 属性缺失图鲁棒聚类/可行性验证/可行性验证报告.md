# 属性缺失图鲁棒聚类：第一轮可行性验证报告

> 本报告保留第一轮实验记录，已根据第二阶段核查修正结论措辞。后续结果与执行顺序见[第二阶段验证报告](第二阶段验证报告.md)和[AMGC 复现核查](AMGC复现核查.md)。原方向规划文档未修改。

## 1. 验证目标

本轮只回答两个问题：

1. 节点级属性缺失是否会在统一聚类流程中造成可测量的性能损害？
2. 特征传播（FP）和 SDCN 式深度聚类是否能在当前电脑环境中跑通？

本轮结果用于决定是否继续实现 AMGC、置信度估计和鲁棒聚类模块，不作为最终论文实验或新颖性证明。

## 2. 环境和数据

- 数据：Cora Planetoid，2708 个节点、1433 维属性、7 个类别；拓扑视为完整。
- 缺失模式：节点级整条属性向量缺失；缺失率为 0、0.2、0.4、0.6、0.8；每个非零缺失率使用 5 个固定随机掩码。
- 当前环境：Python 3.9.21，PyTorch 2.8.0 CPU 版；CUDA 不可用；GTX 1650 当前没有被 PyTorch 使用；PyG 未安装。
- 最小诊断：同一个随机投影和同一个图感知 KMeans 表示比较 complete、zero、mean、neighbor_mean、FP。
- 深度冒烟：保留 SDCN 的 AE + GCN + DEC 交互，使用较小隐藏层和短训练，仅验证训练链路。

### 结果解释

- 缺失属性确实会损害聚类，尤其体现在 NMI 和 ARI；填零和全局均值在 20% 到 80% 缺失时都明显低于完整属性参照。
- FP 在 20% 和 40% 缺失时的 NMI、ARI 高于三个简单填补方法；60% 仍有明显优势，但 ARI 已低于完整属性参照；80% 时 FP 也明显下降。
- 一跳冷启动节点从 20% 缺失时约 27 个增加到 80% 缺失时约 1070 个。这些节点没有直接相邻的观测节点，但其中很多仍能通过多跳获得观测信息；第二阶段已进一步区分多跳可达与所在分量完全无观测节点的情况。
- FP 的补全 RMSE 没有简单降低到最小，但聚类指标更好。这说明“补全误差小”与“聚类有用”不是同一个目标，后续不能只优化重构误差。

## 4. SDCN CPU 冒烟结果

已在 Cora 上适配了 SDCN 的基本结构：自编码器重构、GCN 结构传播、DEC 软分配和目标分布。使用较小隐藏层、预训练 8 轮、联合训练 20 轮，当前 CPU 环境可以完成完整属性、填零和 FP 输入的训练。

短训练结果不稳定，不能作为基线排名。当前默认 8/20 轮重跑记录中，40% 缺失时，FP 的 `pred` 分支 ACC 为 0.2999，填零为 0.2559；80% 缺失时，FP 为 0.2245，填零为 0.2304。这些短训练结果不足以支持方法结论。中途执行的 50/100 轮结果另存为 `results_sdcn_calibration_legacy_50_100.*`，没有混入默认冒烟记录。

训练链路可以完成前向、反向和保存，输出文件为 `results_sdcn_smoke.json` 和 `results_sdcn_smoke.csv`。这不能证明所有联合损失分量均下降或模型已经收敛；联合训练使用动态目标分布，需要结合预测变化和簇占用检查。

## 5. 当前结论

**方向具备初步工程可行性，值得继续验证。** 依据是：缺失损害可测量，FP 式传播提供了可运行的比较方案，SDCN 式深度训练链路在现有 Python 环境中能够跑通。高缺失率下出现大量一跳冷启动节点，但不能据此断言多跳传播全部失效。第二阶段发现基线仍有塌缩和种子波动，尚未达到正式实验的稳定性要求。

当前还不能得出以下结论：FP 已经解决问题；新的置信度方法一定有效；论文具有确定的新颖性；短训练 SDCN 的数值可以直接写入论文。

## 6. 下一阶段执行顺序

1. **先校准基线**：第二阶段已完成分批预训练与 10 组诊断。下一步先比较 AE、q、pred 分支、官方宽度适配和有限的学习率/训练预算设置；稳定后再扩大到 5 个掩码和至少 3 个模型种子，避免仅增加轮数。
2. **加入直接近邻基线**：AMGC 论文和源码已下载核查，尚未运行；先在隔离环境做冒烟，再完整训练。再根据代码可得性考虑 CGIR。没有 AMGC 对比前，不冻结创新点。
3. **扩展缺失模式**：除随机缺失外，加入低度节点优先缺失、类别偏置缺失和冷启动比例控制，验证结论是否只对 MCAR 成立。
4. **再实现研究模块**：先做补全置信度与实际误差的相关性，再做按置信度加权的聚类损失，最后做训练历史稳定性门控。
5. **算力安排**：当前 CPU 可用于调试和小实验；正式多数据集、多种子训练前，建议准备可用的 CUDA PyTorch 环境或使用实验室 GPU。不要为了第一轮验证直接修改当前环境。
